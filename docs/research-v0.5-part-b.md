# Pixel Hotel v0.5 Research — Part B

Scope: (4) voxel/isometric character proportions, face readability, expressions, blink/idle; (5) furniture collision, occupancy, approach tiles, sit/lie/use state machines, stacking, and treadmill/eating/swimming animation. Grounded against current code: `js/voxel.js` (character model + renderer), `js/main.js` (movement/collision/sit flow), `js/data.js` (CATALOGUE), `js/render.js` (draw loop).

## 4. Character proportions, face, expressions, blink/idle

**Sources**
- [Isometric Pixel Art: The Three Proportion Traps](https://neta.art/blog/isometric-pixel-art-proportion-traps) — height should anchor to tile *height* (not width); convention is 4 tile-heights tall; keep the height multiple fixed across the whole cast once chosen.
- [Fundamentals of Isometric Pixel Art](https://pixelparmesan.com/blog/fundamentals-of-isometric-pixel-art) — use isometric construction lines through the head to keep nose/eyes centered and symmetric per facing.
- [The Rules of 16x16 Pixel Art](https://neta.art/blog/16x16-pixel-art-rules) / [sandromaglione: Pixel art eyes](https://www.sandromaglione.com/articles/pixel-art-eyes-techniques-and-styles) — at small scale, eyes read first; keep high contrast between face and hair/hat; 1px eye-position shifts change the read; wider-spaced eyes read younger, tighter/flatter eyes read older or disinterested.
- [Pixel Art Idle Animation: Breathing Sprites in 2–4 Frames](https://piximelon.com/guides/pixel-art-idle-animation/) — 2–4 frame idle at 4–6 FPS; pick **two of three** motions (breath: torso +1px, bob: whole sprite dips, blink: eyes squash one frame) — never sync all three, or it reads robotic; secondary elements (hair, cloth) lag one frame behind the primary motion; blinks fire every 2–4s for one frame, squash don't redraw.
- [Wikipedia: Idle animation](https://en.wikipedia.org/wiki/Idle_animation) — idle loops should be long/varied enough to avoid looking robotic on repeat viewing; blinking + slight arm movement is the baseline "alive" signal.

**Apply to Pixel Hotel**
- Proportions are already consistent (fixed voxel figure in `buildParts`, `js/voxel.js:75`); no change needed there. The risk is in new v0.5 costumes — keep every new `LOOKS` entry using the *same* head/torso/leg box bounds (e.g. head `z: 15..23`, `js/voxel.js:125`) so the "fixed height multiple" rule holds; only hair/outfit boxes should vary.
- Faces only render on the front-facing plane (`headTex`, `js/voxel.js:228`, guarded by `face !== 'front'`) — correct per the contrast/readability sources, but means side/back-facing NPCs currently show no face at all. For v0.5, consider adding a cheaper right/left eye hint (a single shaded pixel-box, not a full face) so idle NPCs standing in profile don't look faceless — matches the "1px eye is readable where 2 aren't" finding.
- **Blink**: add a `blinkUntil` timestamp per mover (player + NPCs) in `js/main.js`/`js/npc.js`, roll it every 2–4s (`now + 2000 + Math.random()*2000`), and feed a `blink: true` flag into `buildParts`'s pose so `headTex` swaps the two eye-white rectangles (`js/voxel.js:239-242`) for a thin closed-lid rect for exactly one render frame. This is a pure data/pose addition, no new geometry system needed.
- **Idle motion**: `buildParts` already parameterizes pose by `stride`/`sit`; add a third low-amplitude `breathe` offset (±0.3–0.5 voxel unit on the torso z0/z1, `js/voxel.js:105`) driven by a slow sine on `now`, only applied when `!walking && !sitting`. Per the "two of three" rule, pair breathe with blink and skip a full-body bob to keep it cheap and non-distracting at hotel scale.
- Keep new idle/blink timers decoupled per-entity (not all NPCs blinking in sync) — directly the Wikipedia/piximelon warning against synchronized motion looking robotic.

## 5. Furniture collision, occupancy, approach tiles, sit/use state machines, stacking, treadmill/eat/swim animation

**Sources**
- [Tile-based video game (Wikipedia)](https://en.wikipedia.org/wiki/Tile-based_video_game) — baseline AABB/grid collision model; confirms grid+flag occupancy is the standard approach for this genre.
- [Mod The Sims: An Introduction to Slots](https://modthesims.info/t/146440) — Sims objects define three slot kinds: **Routing Slots** (where a sim walks to, plus required facing direction, to use the object from outside it), **Container Slots** (invisible holders for an object/sim inside the furniture, e.g. "in the bed"), and **Target Slots** (animation-only reference points). "Snap" transitions a sim from a container slot back to a routing slot so it can walk away again.
- Sims 4 modding docs (`modthesims.info` sleep-pose threads) — animations are driven by a `posture_type` that selects a state machine; e.g. bed sleep uses a transition clip (climbing in, with blanket) before the idle loop, and a separate transition out — i.e. **enter-transition → idle-loop → exit-transition**, not a single pose swap.
- [Multiple Objects on a Tile (Amit Patel / cs.stanford redirect)](https://en.wikipedia.org/wiki/Tile-based_video_game) *(original Stanford page unreachable this session — socket closed on both `http://` and `https://`; falling back to the Wikipedia tile-game article above for the occupancy-grid baseline. Treat the specific "linked list per tile" claim from search snippets as unverified.)*
- [framesprite: swimming sprite waterline layering](https://www.framesprite.com/guides/swimming-sprite-animation-waterline-layers) — split a swimmer into 4 independent layers (body, waterline mask, wake, splash); the waterline is a static mask that hides/shows body regions, decoupled from the swim-stroke animation, so water styling and character animation can change independently.
- Walk-cycle/loop timing references ([slynyrd human walk cycle](https://www.slynyrd.com/blog/2024/5/24/pixelblog-50-human-walk-cycle), general loop-animation search results) — looping in-place animations must have their playback speed matched to perceived effort (e.g., running belt speed), and the last frame must connect cleanly to the first frame with no held pose at the loop seam.

**Apply to Pixel Hotel**
- The codebase already has the Sims 3-slot shape, just implicit: `placedItem.{x,y}` + `rot` is the **routing slot** (target of `findPath` in `trySitPlayer`, `js/main.js:148`), `player.sitting = placed.instanceId` is the **container** reference, and `seatDirFromRot` (`js/main.js:131`) is the routing slot's required facing. Naming/commenting this mapping would make future furniture types easier to reason about, but the mechanism doesn't need to change for simple 1-seat furniture.
- **Current gap vs. sources**: `isBlockedFactory` (`js/main.js:117`) only blocks non-seat furniture outright and has no multi-occupant or "approach from outside, occupy at edge" logic — every seat item is sat *on its origin tile*, so multi-tile seats (`suite_bed` 2×2, `weight_bench` 1×2, `rooftop_sofa`/`sofa` 2×1) only ever have one usable routing slot at `(x,y)` regardless of footprint. For v0.5 "stacking rules" (e.g. two NPCs on a sofa, one per cell), add a `seatOffsets` array per catalogue item (cells relative to origin that are each an independent routing+container slot) and have `occupantTilesExcluding` treat each occupied seat offset as taken rather than treating the whole footprint as one slot.
- **Approach tiles for non-seat interactables** (treadmill, buffet, espresso bar, etc.): these are currently just solid blockers (`if (!item.seat) return true;`, `js/main.js:124`) with no "walk up and face it" interaction at all. Model each per the Sims pattern: one routing slot adjacent to the footprint (e.g., `{dx, dy, dir}` computed from `rot`, analogous to `seatDirFromRot`) that `tryUsePlayer(placedItem)` paths to, sets `player.using = placed.instanceId` + `player.dir = requiredDir`, instead of adding a new blocking type.
- **State machine shape**: adopt enter-transition → loop → exit-transition explicitly rather than snapping straight into a loop pose, matching the Sims bed pattern. Concretely: `player.activity = { itemId, phase: 'enter'|'loop'|'exit', startedAt }`; `phase` advances on a timer (e.g. enter for 1 step duration, then loop until the player moves, then a short exit before `tryWalkPlayer` is allowed to actually release the tile). This reuses the existing `pendingSit`/`sitting` transition point in `onPlayerArrive` (`js/main.js:201`) rather than introducing a parallel system.
- **Treadmill** (`treadmill`, footprint 1×2, currently static decor): drive the existing walk-cycle leg pose (`buildParts` stride branch, `js/voxel.js:84-97`) at a fixed stride rate while `player.using === treadmillId && phase === 'loop'`, with `player.dir` locked facing the console — i.e. reuse the walking leg animation in place, with the room/world position frozen, exactly the "in-place walk, loop speed matched to perceived belt speed" pattern from the walk-cycle sources. No new leg-pose code needed, just drive the existing stride oscillator without moving `x/y`.
- **Eating** (buffet/dining/chef station, café table): no existing "sit and do a repeated small-prop gesture" pose. Cheapest version per the idle-animation sources: reuse the seated arm pose (`sid` branch in `buildParts`, `js/voxel.js:113-121`) and add a slow periodic forearm-lift (same amplitude/timing class as the proposed breathe idle) synced to a fork/cup prop already drawn as part of the furniture sprite (`dining_table`/`cafe_table` builders in `js/sprites.js`) rather than modeling food-in-hand on the character.
- **Swimming** (`pool_water`, 2×2 flat decor): apply the framesprite 4-layer split directly — draw the character's normal walk/idle figure first, then redraw a pool-colored translucent rectangle (reusing the existing per-tile iso diamond draw already used for `flat` items, `js/render.js` furniture pass) over the lower half of the character's bounding box (everything below roughly leg-top `z`) so legs appear submerged; animate only arm boxes (already isolated in `buildParts`, `js/voxel.js:109-122`) in a slow alternating stroke using the same `stride`-oscillator mechanism as walking, decoupled from actual tile movement. No new masking primitive required — it's an extra fill rect drawn after the character blit in `drawCharacter` (`js/render.js:673`), gated on `player.using === poolWaterId`.
- **Stacking rule of thumb**: keep it 1 occupant per 1×1 seat cell (already true), and for multi-cell furniture cap occupants at the number of defined `seatOffsets`, never at footprint-area — a 2×2 bed should still default to 1 sleeper unless a feature explicitly wants a loveseat-style 2-up sit.
